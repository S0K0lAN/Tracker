# Focus Flow

Персональный local-first таск-трекер на React/TypeScript. Он объединяет
быстрый захват задач, Сегодня, проекты, список и доску Входящих, календарь и
дедлайны, матрицу Эйзенхауэра, поиск и фильтры, таймер фокуса, привычки,
корзину/архив и настраиваемое оформление.

Текущая реализация включает браузерный MVP и собираемую Tauri 2 Android-
оболочку. В браузере используются `localStorage`, data URL, Web Speech и
обычное скачивание. Android использует приватный атомарный JSON,
content-addressed файлы вложений, SAF export, системный PDF viewer, нативную
диктовку `ru-RU`, safe-area/system-bar bridge и Google `AuthorizationClient`.
Физический OnePlus Ace2 и live OAuth smoke, release signing/Play Store и
Ubuntu-сборка пока не подтверждены.

## Запуск с нуля

Понадобятся [Git](https://git-scm.com/downloads), Node.js 18.19 или новее и
`npm` (он устанавливается вместе с Node.js). Для воспроизводимых проверок
предпочтительна поддерживаемая LTS-версия Node. На Node.js 26 приложение и
production-сборка работают, но Vitest/jsdom конфликтует с экспериментальным
глобальным Web Storage Node; временный способ запуска тестов указан ниже.
Проверить версии можно так:

```bash
git --version
node --version
npm --version
```

1. Склонируйте репозиторий и перейдите в папку проекта:

   ```bash
   git clone https://github.com/S0K0lAN/Tracker.git
   cd Tracker
   ```

2. Установите зафиксированные в `package-lock.json` зависимости:

   ```bash
   npm ci
   ```

3. Запустите сервер разработки:

   ```bash
   npm run dev
   ```

4. Откройте на компьютере `http://localhost:4173`. При первом открытии
   приложение автоматически загрузит демонстрационные данные.

Чтобы остановить сервер, вернитесь в терминал и нажмите `Ctrl+C`. При
следующих запусках достаточно выполнить `cd Tracker` и `npm run dev`.

### Production-сборка локально

```bash
npm run build
npm run preview
```

После запуска откройте `http://localhost:4173`.

### Открытие с телефона

Обычный `npm run dev` слушает только loopback и не публикует локальные данные
в сеть. Для явного запуска на телефоне выполните `npm run dev:lan`, подключите
телефон и компьютер к одной доверенной Wi-Fi сети и откройте
`http://<локальный-IP-компьютера>:4173`. Текущий локальный IP можно узнать
командой `ip -4 -brief address show scope global`.

В LAN-режиме любой клиент этой сети может открыть приложение в браузере.
Не используйте недоверенную Wi-Fi сеть и не пробрасывайте порт 4173 в интернет:
это сервер разработки без production-защиты, HTTPS и авторизации.

### Android debug APK через Tauri 2

Браузерный LAN-режим выше не устанавливает приложение. Для нативной Android-
оболочки используются локальные toolchains из `Tracker/.tooling` и три
воспроизводимых скрипта:

```bash
bash scripts/mobile-env.sh
source scripts/mobile-env.sh
scripts/android-build.sh
```

`android-build.sh` собирает debug APK только для `arm64-v8a` (в том числе для
OnePlus Ace2) и сразу проверяет подпись, 16 KiB alignment, SDK levels,
permissions и ABI. Готовый APK можно повторно проверить явно:

```bash
scripts/android-verify.sh <путь-к-debug-apk>
```

Версии окружения зафиксированы в скрипте: Rust 1.98.0, Android Platform 36,
Build Tools 36.1.0, NDK 29.0.14206865 и ADB 37.0.1. Скрипт окружения не
устанавливает и не обновляет toolchains; при неполном `.tooling` он завершается с
инструкцией. Первая Gradle/Cargo-сборка может дозагрузить
зафиксированные зависимости в проектные кэши. Полная подготовка OnePlus Ace2,
установка через ADB, logcat, offline/persistence и UX checklist находятся в
[`docs/android-device-testing.md`](docs/android-device-testing.md).

Это артефакт для физического smoke, не подписанный Google Play release. Android
использует нативный Google `AuthorizationClient`, а не неподдерживаемый в WebView
GIS JavaScript; реализованный bridge запрашивает только `drive.appdata` и держит
access token в памяти. Для live smoke всё ещё нужны отдельный Android OAuth
client, SHA-1 debug-сертификата и Google Play Services на устройстве. Web OAuth
остаётся отдельным и не меняется.


`npm run check` объединяет только unit/component-тесты и production-сборку;

unit/component-тестов, успешная production-сборка и 50/50
Playwright-сценариев. Проверенный `arm64-v8a` debug APK имеет SHA-256

Датированное evidence и исторические результаты зафиксированы в
[`docs/feature-acceptance.md`](docs/feature-acceptance.md).

## Демо-данные

При первом запуске приложение создаёт воспроизводимый демонстрационный набор:
проекты, задачи разных приоритетов и состояний, пересекающиеся временные слоты,
отдельные дедлайновые диапазоны, обычные активные и завершённые задачи «Весь
день» без дедлайна, недатированные задачи, теги, подзадачи, напоминания,
вложения и историю привычек. Даты рассчитываются относительно дня запуска;
набор отдельно показывает отсутствие срочности по умолчанию и автоматический
сигнал у приблизившегося дедлайна.

Если в браузере уже есть локальные данные, откройте «Настройки → Данные» и
нажмите «Сбросить», чтобы загрузить актуальный demo-набор из
`src/domain/seed.ts`. Существующие локальные изменения при этом будут заменены.

## Резервная копия JSON

В «Настройки → Локальные данные» можно скачать переносимую резервную копию и
загрузить её обратно. Перед импортом Focus Flow проверяет формат и вложенные
данные, показывает количество задач, проектов, привычек и фильтров, а замену
выполняет только после явного подтверждения. Предыдущее локальное состояние
остаётся доступным по кнопке «Восстановить».

Файл ограничен 10 МБ и не содержит OAuth-сессию, выбранный sync provider или
его device-local настройки. Поэтому JSON можно перенести на другое устройство,
не перенося авторизацию Google. Задачи, проекты, привычки, фильтры, Pomodoro,
оформление и встроенные в браузерный snapshot вложения входят в копию.

Маршруты: `/today`, `/inbox`, `/projects`, `/projects/:projectId`, `/calendar`,
`/matrix`, `/search` (запрос сохраняется в URL), `/habits`, `/trash`,
`/settings`.

## Что реализовано

- Создание и редактирование задач с проектом, датами, важностью, тегами,
  напоминаниями, подзадачами и вложениями. Обычную задачу без дедлайна можно
  одним нажатием сделать задачей «Весь день» на текущую локальную дату;
  `allDayDate` взаимно исключается с началом, длительностью, дедлайном и
  настройками срочности, а длительность отдельно взаимоисключается с дедлайном.
- По умолчанию задача не показывает срочность. У активной задачи с дедлайном
  сигнал появляется при наступлении порога проекта или задачи; до порога и без
  дедлайна низкая эффективная срочность используется только матрицей и фильтрами.
- Аварийный журнал текстового черновика задачи с debounce, явным
  восстановлением/удалением и быстрым сохранением через `Ctrl/Cmd+Enter`.
- Отдельный просмотр существующей задачи; редактор и действия запускаются явно.
- Просмотр изображений/PDF/текста, голосовой capture с русским parser и
  текстовым fallback: обычная дата задаёт начало, «до»/«дедлайн» — дедлайн.
- Прямые URL проектов, переход к проекту из поиска, восстановление поискового
  контекста через Back/Forward, сохранённые фильтры и сортировка Входящих.
- Входящие по умолчанию для неразобранных задач без проекта, `allDayDate`,
  начала и дедлайна, с быстрым фильтром «Все» для прежнего общего
  набора; доступны список и доска, а календарь остаётся самостоятельным
  маршрутом основной навигации. Длинный
  список сохраняет windowed performance и доступен целиком с клавиатуры/AT.
- Календарь на год, месяц, неделю, три дня и день; периоды листаются кнопками,
  свайпом или мышью, ячейка месяца открывает полный список, а высота внутридневного
  блока задаётся длительностью. Обычные date-only задачи занимают однодневную
  полосу в секции «Весь день» недели/трёх дней/дня и зелёную строку в месяце;
  дедлайны показаны одной полосой `startAt → deadline` без временного дубля.
  Номер текущей локальной даты отмечен компактно, без обводки всей ячейки или
  колонки. Выполненные задачи остаются видимыми в календаре.
- Мягкое удаление, восстановление, окончательное удаление и отдельный архив.
- Привязанный к задаче 25-минутный таймер фокуса и накопление минут.
- Создание привычек и редактирование названия, описания и одной из десяти
  векторных иконок. Ритм рассчитывается по сохранённому `targetDays` и только
  с локального дня `createdAt`;
  пользовательская настройка расписания и цвета ещё не реализована.
- Светлая/тёмная тема, акценты, глобальные семейство/масштаб шрифта,
  встроенные и пользовательский фон.
- Schema v10, миграции schema v1–v9, проверка ссылочной/структурной целостности,
  лимиты сложности и localStorage backup/recovery.
- Переносимый JSON-export/import с предварительной проверкой, сводкой и отменой
  импорта через отдельную предыдущую копию.
- Глубокая проверка импортируемых сущностей и безопасные локальные `data:`-URL
  вложений; повреждённые копии помещаются в quarantine до восстановления.
- OAuth-подключение Google Drive и три независимых действия с данными:
  «Получить», «Отправить» и умное «Синхронизировать»; автосинхронизация
  использует тот же безопасный reconcile-сценарий.
- Реестр провайдеров удалённого хранилища: новый адаптер подключается без
  изменения доменной модели задач, а сохраняемые config-поля обязаны быть
  явно классифицированы как публичные.
- Инъецируемый `StorageAdapter` и сериализованная/coalescing очередь локальных
  записей не позволяют запоздалой старой записи перезаписать новую.
- Минимальный in-process реестр расширений. Это пока каркас, а не Plugin API
  v1: permissions, sandbox, version negotiation и выполнение стороннего кода
  не реализованы.
- Unit/component, Playwright E2E, WCAG AA color-contrast и windowed performance gate на 500
  задач; GitHub Actions повторяет полный gate для PR и `main`.

## Статус Google Drive

В браузере OAuth работает через Google Identity Services, а Android-сборка
использует системный Google `AuthorizationClient`; оба пути передают сессию в
общий Drive runtime с минимальным scope `drive.appdata`. Приложение умеет найти существующую
копию `focus-flow-data.json`, загрузить её, создать новую, обновлять после
локальных изменений и обнаруживать изменение удалённой ревизии. При первом
согласовании разных копий пользователь явно выбирает источник; перед импортом
локальное состояние сохраняется в отдельный backup.

Вход через Google только авторизует текущую вкладку и сам по себе не переносит
данные. После подключения доступны три явных действия:

- «Получить из Google Drive» читает remote-копию, но ничего не записывает в
  Drive. Если копии различаются, приложение показывает сравнение и применяет
  remote только после подтверждения, предварительно сохранив локальный rollback
  backup. Если файла в Drive нет, локальные данные остаются без изменений.
- «Отправить в Google Drive» передаёт локальную копию, но не применяет remote к
  приложению. Запись проверяет ожидаемую revision; при обнаружении другой копии
  требуется явное подтверждение перезаписи.
- «Синхронизировать» сравнивает локальную и удалённую метадату и безопасно
  выбирает направление. Автосинхронизация использует этот же reconcile, а не
  принудительное получение или отправку.

Drive media upload не документирует атомарный compare-and-swap: приложение
повторно проверяет ID/version непосредственно перед записью и никогда не
разрешает обнаруженный конфликт автоматически, но между проверкой и `PATCH`
остаётся best-effort окно гонки. Для полной межустройственной гарантии нужны
будущие immutable revisions/base snapshot и трёхсторонний merge.

### Настройка Google OAuth в браузере

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте или
   выберите проект, включите **Google Drive API** и настройте OAuth consent
   screen.
2. В **Google Auth Platform → Audience** выберите аудиторию **External**. Пока
   приложение находится в режиме **Testing**, добавьте используемые Google-
   аккаунты в список **Test users** — одного членства в IAM проекта недостаточно.
3. Создайте credential типа **OAuth client ID → Web application**. Добавьте
   точный адрес приложения в **Authorized JavaScript origins**, например
   `http://localhost:4173` для локальной разработки и открывайте приложение
   именно по этому адресу: OAuth origin должен совпадать полностью. Для
   production используйте стабильный HTTPS origin.
4. Один раз задайте публичный Client ID в конфигурации сборки. Для локального
   запуска скопируйте `.env.example` в `.env.local` и замените пример:

   ```bash
   cp .env.example .env.local
   ```

   ```dotenv
   VITE_GOOGLE_CLIENT_ID=000000000000-example.apps.googleusercontent.com
   ```

   Client secret браузерному приложению не нужен и не должен попадать в
   `.env.local`. Для размещённой версии задайте `VITE_GOOGLE_CLIENT_ID` в
   build environment хостинга до `npm run build`.
5. Перезапустите `npm run dev`, откройте «Настройки → Синхронизация», выберите
   Google Drive и нажмите «Войти через Google». Focus Flow откроет защищённое
   окно Google; конечному пользователю не нужно видеть или вводить Client ID.
   После авторизации отдельно выберите «Получить», «Отправить» или
   «Синхронизировать» — сам вход данные не изменяет.

Client ID является публичным идентификатором приложения и попадает в браузерную
сборку, но не является пользовательской настройкой. Access token существует
только в памяти вкладки и исключён из `localStorage` и удалённого snapshot.
После перезапуска выбранный провайдер, удалённая ревизия и настройка
автосинхронизации сохраняются, но браузер попросит нажать «Продолжить с Google»,
чтобы получить новый краткоживущий token. Это ограничение безопасной
browser-only OAuth-модели: полностью фоновое постоянное подключение потребует
BFF с защищённым refresh token. Android-сборка также намеренно не сохраняет
credential и получает краткоживущий token через Google Play Services.

OAuth с адреса телефона вида `http://192.168.x.x:4173` не следует считать
production-сценарием. Для входа с телефона разверните приложение на HTTPS и
добавьте этот origin в Google Cloud Console.

### Настройка Google OAuth в Android debug APK

Создайте OAuth client типа **Android** для package
`io.github.s0k0lan.focusflow.debug` и SHA-1, который печатает
`scripts/android-verify.sh`. Web client ID и client secret в APK не нужны.
Добавьте тестовый аккаунт в Audience, убедитесь, что Drive API включён, затем
проверьте вход и отдельные действия «Получить»/«Отправить» на устройстве по
[`docs/android-device-testing.md`](docs/android-device-testing.md). Для release-
package и production-сертификата понадобится отдельный Android credential.

Автоматический E2E проверяет OAuth-поток с имитацией Google API; реальный live
smoke не выполняется без отдельного тестового Client ID и аккаунта. Поэтому
репозиторий не заявляет проверенную live-совместимость с конкретной Google
конфигурацией.
